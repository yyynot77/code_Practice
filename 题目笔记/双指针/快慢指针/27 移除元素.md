# 27. 移除元素

官方链接：[27. Remove Element](https://leetcode.com/problems/remove-element/)

## 一句话结论

这题不是“真的删除元素”，而是“把应该保留的元素覆盖到数组前面，并返回新长度”。

## 题目要求

给定数组 `nums` 和值 `val`，原地移除所有等于 `val` 的元素，返回剩余元素数量。

只要求数组前 `k` 个元素正确，后面的元素不用管。

## 正确思路：快慢指针

- `fast` / `i`：负责扫描每一个元素。
- `slow` / `left`：表示下一个有效元素应该写入的位置。

```java
class Solution {
    public int removeElement(int[] nums, int val) {
        int slow = 0;

        for (int fast = 0; fast < nums.length; fast++) {
            if (nums[fast] != val) {
                nums[slow] = nums[fast];
                slow++;
            }
        }

        return slow;
    }
}
```

## 为什么这样写

遇到不等于 `val` 的元素，说明它应该保留，就写到 `nums[slow]`。

写完以后 `slow++`，表示下一个保留元素应该写到后面一个位置。

遇到等于 `val` 的元素，直接跳过，不写入。

## swap 写法

也可以写成交换：

```java
class Solution {
    public int removeElement(int[] nums, int val) {
        int left = 0;

        for (int i = 0; i < nums.length; i++) {
            if (nums[i] != val) {
                swap(nums, i, left);
                left++;
            }
        }

        return left;
    }

    private void swap(int[] nums, int i, int j) {
        if (i == j) {
            return;
        }
        int temp = nums[i];
        nums[i] = nums[j];
        nums[j] = temp;
    }
}
```

这个写法能通过，但本题更推荐覆盖写法。

原因：

- 这题只要求前 `k` 个元素正确，不要求被删除的元素保留到后面。
- 覆盖写法只需要一次赋值。
- swap 写法通常需要三次赋值，逻辑也更重。
- swap 更像“把两个位置的元素互换”，但本题本质是“筛选并覆盖”。

## 和排序的区别

这题看起来像有两个指针在扫描，但不是插入排序，也不是快排。

- 插入排序：维护一个有序区，把当前元素插入到合适位置。
- 快排：围绕 pivot 做分区，然后递归处理左右部分。
- 移除元素：只做一次线性扫描，把保留元素放到数组前面。

更准确地说，它像“稳定筛选”：

```text
把所有 nums[i] != val 的元素，按原顺序写到前面。
```

## 复杂度

- 时间复杂度：`O(n)`
- 空间复杂度：`O(1)`

## 容易犯错

- 想用额外队列或新数组，但题目要求原地修改。
- 把 `val` 写成 `target`。
- 返回数组，而不是返回新长度。
- 忘记数组后面的元素不重要。
- 混淆 `slow` 和 `fast` 的职责。

## 面试复述

我用快慢指针。`fast` 扫描整个数组，`slow` 记录下一个有效元素应该写入的位置。当 `nums[fast] != val` 时，把它写到 `nums[slow]`，然后 `slow++`。遍历结束后，`slow` 就是不等于 `val` 的元素个数，也就是新长度。

## 复盘提问

- 如果没有元素等于 `val`，数组会发生什么？
- 覆盖写法和 swap 写法有什么区别？
