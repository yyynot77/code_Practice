# 15. 3Sum

- 难度: Medium
- 模式: 排序 + 固定一位 + 双指针去重
- 结论: 三数之和不是“三层循环优化题”, 而是“排序后把两数之和模板嵌进来”

## 模板识别

- 题目要找所有不重复三元组
- 既要考虑和, 又要考虑去重
- 一旦出现“所有不重复组合 + 有序移动”, 先想排序

## 稳定写法

```java
Arrays.sort(nums);
List<List<Integer>> ans = new ArrayList<>();
for (int i = 0; i < nums.length - 2; i++) {
    if (i > 0 && nums[i] == nums[i - 1]) {
        continue;
    }
    int left = i + 1, right = nums.length - 1;
    while (left < right) {
        int sum = nums[i] + nums[left] + nums[right];
        if (sum == 0) {
            ans.add(Arrays.asList(nums[i], nums[left], nums[right]));
            left++;
            right--;
            while (left < right && nums[left] == nums[left - 1]) left++;
            while (left < right && nums[right] == nums[right + 1]) right--;
        } else if (sum < 0) {
            left++;
        } else {
            right--;
        }
    }
}
return ans;
```

## 三处去重

- 固定项去重: 防止相同首元素重复启动同一轮搜索
- 命中答案后左指针去重: 防止第二个数重复
- 命中答案后右指针去重: 防止第三个数重复

## 为什么一定先排序

- 排序后, `sum < 0` 才能放心右移左指针, `sum > 0` 才能放心左移右指针
- 排序后, 重复元素才会聚在一起, 去重逻辑才简单可靠
- 不排序就很难同时保证“找全答案”和“去重正确”

## 容易错的点

- 漏掉固定项去重
- 命中答案后只移动一次指针, 没有跳过重复值
- `left` / `right` 去重时比较的是移动后的相邻值, 容易写反
- 只会背代码, 说不清为什么复杂度是 `O(n^2)`

## 面试复述

- 先排序, 再把问题拆成“固定一个数 + 剩下部分做两数之和”
- 外层枚举 `i`, 内层双指针线性扫描
- 每个 `i` 对应一次 `O(n)` 搜索, 总时间 `O(n^2)`
- 去重是正确性的核心, 不是附属细节
