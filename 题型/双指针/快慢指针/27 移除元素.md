# 27. 移除元素

- 难度：Easy
- 模式：快慢指针 / 原地覆盖
- 结论：快指针扫描，慢指针写入

## 模板识别

- 看到“原地删除”。
- 看到“返回新长度”。
- 看到“数组前 k 个元素满足要求”。
- 题目不要求保留数组后面的内容。

## 题解骨架

```java
int slow = 0;

for (int fast = 0; fast < nums.length; fast++) {
    if (nums[fast] != val) {
        nums[slow] = nums[fast];
        slow++;
    }
}

return slow;
```

## 指针含义

| 指针 | 含义 |
| --- | --- |
| `fast` | 扫描指针，负责检查每个元素 |
| `slow` | 写入指针，表示下一个有效元素的位置 |

## 容易错的点

- `slow++` 写在 `if` 外面。
- 返回 `nums`，但题目要求返回 `int`。
- 用额外数组或队列，导致空间复杂度变成 `O(n)`。
- 以为要把数组后面的元素清空。
- 把这题误解成排序题。

## 面试复述

这题的核心是原地筛选。`fast` 遍历数组，遇到不等于 `val` 的元素就写入 `slow` 位置。`slow` 左边始终都是应该保留的元素，遍历结束后 `slow` 就是新数组长度。

## 复盘检查

- 能否解释 `slow` 左边区间的含义？
- 能否手动模拟 `[3,2,2,3]`、`val = 3`？
- 能否说清楚为什么后面的元素不用管？
- 能否比较覆盖写法和 swap 写法？
